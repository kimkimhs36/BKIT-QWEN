# BKIT STUDY OS

한국 고등학생을 위한 로컬 우선 생활·학습 관리 앱 v1.1. 계획의 완벽함보다 **첫 5분 시작, 기록한 학습량, 무너진 계획의 회복**을 우선합니다. 시간대는 Asia/Seoul이며 사용자 데이터와 실제 시간으로 화면을 계산합니다.

기존 CRASH//WEEK와 분리된 `study-os/` 앱입니다. 루트 `index.html`, `styles.css`, `app.js`, `README.md`, `CNAME`은 수정하지 않았습니다. 기존 `crashweek.v3` 저장 키도 읽거나 삭제하지 않습니다.

현재 공개 앱: [TOHEŞAR × BKIT](https://teambkit.com/). 개발 원본은 `feat/study-os-visual-v2` 브랜치의 `study-os/`입니다. 아래 v1 Sites 배포 관련 설명과 [DEPLOYMENT.md](DEPLOYMENT.md)는 초기 개발 이력입니다. 현재 공개 배포는 `.github/workflows/publish-teambkit.yml`이 검증한 정적 파일을 `main`에 게시하고, 별도 Pages 성공 및 `release.json`의 원본 커밋 일치까지 확인합니다.

2026-10-18 재개 버전: ‘오늘 할 일 정리 → 사진 없이 과제 확인 → 확인 후 저장 → 5분 시작’. 사진을 첨부했다면 무료 기기 내 한글·영어 글자 추출을 선택할 수 있으며, 공부 화면에서도 연결된 사진을 펼쳐볼 수 있습니다. 외부 AI 서버는 현재 demo 상태입니다. API 키·결제 없이 기본 학습과 OCR을 사용할 수 있습니다. 정확한 연동 현황·비밀 설정·남은 사용자 행동은 [API-SETUP.md](API-SETUP.md)를 확인하세요.

## 바로 실행

Node.js 22 이상을 권장합니다.

```sh
cd study-os
npm ci
npm run dev
```

개발 URL: `http://localhost:5173/study-os/`. 서버나 AI 계정 없이 P0 기능 전체를 사용할 수 있습니다. 기본 정적 버전은 AI 서버에 네트워크 요청을 하지 않습니다.

```sh
npm run typecheck
npm test
npm run build
npm run preview -- --port 4173
```

프로덕션 로컬 미리보기: `http://localhost:4173/study-os/`. PWA 오프라인 캐시는 개발 서버가 아니라 **프로덕션 빌드**에서 활성화됩니다. 한 번 온라인으로 로드하고 서비스 워커 설치가 완료되어야 합니다.

브라우저 자동 검증:

```sh
npx playwright install chromium
npm run test:e2e
```

이 환경에서는 `/usr/bin/chromium`을 사용합니다. 다른 컴퓨터는 `playwright.config.ts`의 `launchOptions.executablePath`를 제거하거나 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 설정하세요. 테스트는 자동으로 4173의 빌드 미리보기를 시작합니다. 기존 미리보기 서버가 있으면 같은 빌드인지 확인하세요.

## WHAT WORKS NOW

- 한국어 모바일 대시보드: 날짜·시각, 현재 행동, 다음 실제 수업, 준비까지 남은 시간, 실제 기록 집계, 미완료·마감 임박 과제, 승인한 계획의 시작 지연.
- 학교·학원·개인 고정 일정: 월~일 반복, 수업별 시작·종료·준비·이동·안전 여유·준비물, 과목 연결, 날짜 한정 일정과 제외 날짜. 오늘·내일 조회 및 주간 시간표. 최초 시간표는 비어 있습니다.
- 과거 수·금 수학 / 일 국어 일정은 **안내만** 표시하며, 확인 후 사용자가 입력합니다.
- 학원 준비→출발→예상 도착→수업 시각 계산. 지각을 피하려고 위험하게 서두르도록 안내하지 않습니다.
- 과제 생성·수정·삭제: 종류·과목·마감·중요도·전체/남은 분량·상태·제출·메모·링크. 마감 미확정은 확인 필요. 학습 완료와 제출 완료는 별개입니다.
- 5·15·25·사용자 지정 집중 세션: 실제 시작·종료, 일시정지·사유, 중단 사유, 문제 수·개념·자기평가. 새로고침 중에도 세션 상태 보존. 수면·식사·고정 일정 시작 시 자동 일시정지하며, 브라우저가 늦게 깨어나도 첫 보호 일정 시작까지만 경과 시간을 기록합니다.
- 새 세션은 실제 집중 구간(start/end)을 저장해 일시정지 시간을 날짜별 집계에서 정확히 제외합니다. 기존 v1 백업은 구간 정보가 없어도 읽을 수 있고 기존 기록은 유지됩니다.
- TODAY의 제출 확인 알림과 TASKS의 제출 확인 목록, 한 번 터치하는 제출 기록. 숙제·수행평가는 학습 완료 후에도 제출 전까지 주의 목록에 남습니다.
- 타이머 경과 시간은 학습 성과로 처리하지 않습니다. 실제 문제·개념은 직접 입력합니다. 과제 완료를 자동으로 가정하지 않습니다.
- 오답 기록과 다음 날 복습 목록, 답을 가린 능동 회상·문제 재시도 안내, 재시도 완료 체크.
- 규칙 기반 계획 복구: 현재부터 7일 이내 마감 전 빈 구간 검색, KEEP/REDUCE/MOVE/DROP 분류, 첫 5분 행동, 변경 전후 비교, 사용자 승인, 한 단계 실행 취소. 1–4분만 남은 짧은 과제도 안전하게 배치합니다.
- 수업·준비·이동·식사·최소 수면 보호, 학습 사이 휴식, 지난 시각 배치 금지, 마감 이후 배치 금지, 완료 과제 제외, 직접 고정한 학습 시간 보호. 선택·마감 없는 과제만 DROP 가능하며 과제 데이터는 삭제하지 않습니다.
- AI 결과는 Zod 구조 검증과 일반 코드 시간 검증을 모두 거칩니다. 정해진 안전 시간 배치를 모델이 임의로 변경할 수 없습니다.
- JSON 내보내기·스키마 검증 가져오기·교체 전 확인, 로컬 저장 오류/손상 경고, 다른 탭의 쓰기 감지 시 저장 잠금. 오류 상태에서 기존 저장본을 자동 덮어쓰지 않습니다.
- 날짜 확정 여부를 유지하는 시험 원점수·목표 입력, 과목별 타이머/문제량, 최근 7일 기록, 장기 목표, 기록 기반 코치 요약. 가천대학교 전형 세부 정보는 공식 자료 확인 필요로 표시합니다.
- 설치형 PWA 매니페스트, iPhone 아이콘, 자체 범위 오프라인 캐시, 로컬 폰트, 14일 `.ics` 캘린더 내보내기. 기존 사이트 캐시는 건드리지 않습니다.
- 키가 없는 기본 모드는 **Demo AI Mode · 규칙 기반**이며 실제 AI 연결처럼 표시하지 않습니다.

### 계획 계산 범위

복구 엔진은 과제별 집중 가능한 **다음 한 구간**을 추천합니다. 전체 숙제를 다 끝낼 수 있다고 주장하지 않습니다. 축소된 과제의 나머지 분량은 그대로 남으며, 완료 기록 후 다시 복구할 수 있습니다. 슬롯은 검토할 시간을 위해 계산 시각보다 약 2–3분 뒤부터 제안합니다. 검토 도중 시작 시간이 지나면 재계산해야 승인할 수 있습니다.

고정 일정끼리 충돌하면 원본을 유지하고 시간표에서 경고합니다. 시간표 등록 자체를 막거나 수업을 자동 이동하지 않습니다. 수업이 수면과 겹치면 현실 일정을 확인해야 합니다. 기본 생활 설정은 기상 07:00·취침 23:00·최소 수면 8시간·식사 18:00 45분·구간 사이 휴식 5분이며, 실제 수업 데이터나 성취 기록이 아닙니다. 설정과 고정 일정으로 수정하세요.

## WHAT REQUIRES CONFIGURATION

### 서버 AI 연결

사용자 승인 후 별도 개인 계정에서 API 키와 최신 요금을 설정합니다. 이 작업에서는 키 등록·결제·실제 유료 호출을 하지 않았습니다.

```sh
cp .env.example .env
# .env에서 API 키, 모델, 현재 입력/출력 단가를 설정
# 브라우저 요청을 사용하려면 VITE_AI_API_ENABLED=true 설정 후 dev 서버 재시작
npm run server
# 다른 터미널: npm run dev
```

서버는 기본 `127.0.0.1:8787`에만 바인딩합니다. Vite 개발/미리보기의 `/api` 프록시가 연결합니다. 정적 GitHub Pages만으로는 이 서버를 실행할 수 없습니다.

- `ProviderAdapter` 인터페이스와 `OpenAICompatibleAdapter` 구현을 분리했습니다. 기본 후보는 OpenAI `gpt-4.1-mini`이며 HTTPS 기반 OpenAI 호환 엔드포인트로 교체할 수 있습니다. Gemini 고유 API처럼 규격이 다른 공급자는 새 어댑터를 구현하세요. 공급자 호환성을 실제 연결 없이 보장하지 않습니다.
- `POST /api/plan`: 결정·시간 배치는 규칙 엔진이 계산합니다. 실제 모델은 이유와 첫 행동을 한국어로 설명합니다. 시간·분류·ID를 변경한 출력은 거절하고 규칙 기반 결과로 복구합니다. 모델이 DB를 수정할 권한은 없습니다.
- `POST /api/coach`: 최근 최대 20개 세션의 학습량·자기평가와 미완료 과제 요약으로 짧은 학습 제안을 생성합니다. AI 조언은 사용자에게 표시될 뿐 자동 실행되지 않습니다.
- `GET /api/health`: demo/configured 상태와 `push:false`를 반환합니다. configured는 키·단가 설정을 뜻하며 실제 공급자 통신 성공을 보장하지 않습니다. 개별 응답의 `mode:live`는 실제 호출 성공과 스키마 검증을 뜻합니다.
- 빈 API 키 또는 0 단가에서는 외부 호출을 하지 않습니다. 기본 한도는 **UTC 하루 10회·추정 최대 $0.10**입니다. 일일 비용은 UTF-8 프롬프트 바이트를 입력 토큰 상한으로 보수적으로 환산하고 최대 출력 2,200토큰을 미리 예약합니다. 가격은 사용자가 확인한 단가를 사용하므로 공급자 청구서와 비교해야 합니다.
- 요청 사이 1.5초 제한, 요청 본문 128KB, 모델 프롬프트 16KB, 15초 공급자 타임아웃. 시간 오차가 5분보다 큰 클라이언트 요청은 거절합니다.
- `.runtime/budget.json`에 호출 횟수·예약 비용·입출력 토큰을 저장합니다. 실패한 요청도 예약분을 유지해 재시작으로 상한을 피하지 못하게 합니다. `.runtime/usage.jsonl`에는 경로·시각·토큰 수만 기록하며 학습 프롬프트·학생 기록·키를 쓰지 않습니다. `.runtime`은 커밋에서 제외됩니다.
- 장부는 **단일 프로세스·영속 디스크**용입니다. 여러 서버나 휘발성 서버리스에 그대로 배포하면 전역 한도를 보장하지 못하므로 트랜잭션 DB 한도로 교체해야 합니다.
- 프런트엔드 전송은 버튼을 누를 때만 발생합니다. 계획 요청의 과제 메모·링크·세션·성적·장기 목표는 제거됩니다. 실제 모델에는 과제명·과목·마감·분량과 규칙 기반 배치만 전달합니다. 코치에는 과목·문제 수·시간·자기평가만 전달합니다.
- 개발용 Origin 허용 목록은 인증이 아닙니다. **유료 API를 공개하기 전 서버 인증, 사용자 경계, HTTPS, 호출 제한을 마련해야 합니다.** 공개 Vite 개발 서버에 유료 키를 붙여 운영하지 마세요. 현재 공개 API 운영·로그인은 구현하지 않았습니다.

### 알림

백그라운드 Web Push는 구현하지 않았습니다. iOS 16.4 이상 홈 화면 PWA 지원 가능성과 실제 예약 푸시 구현은 다릅니다. 사용자 권한, 구독 저장, VAPID, 서버 예약 발송이 다음 작업입니다. 현재는 `.ics`를 캘린더에 가져온 뒤 기기의 알림 설정을 확인해야 합니다. 캘린더 앱별 가져오기와 알림 동작은 실제 iPhone에서 검증해야 합니다.

## WHAT IS NOT IMPLEMENTED

- 앱 내부 다중 사용자 DB·인증, 기기 간 동기화, 서버 푸시·예약 작업. 배포 페이지의 본인 계정 접근은 Sites 인증으로 제공하며 기록 동기화와는 별개입니다.
- 실제 iPhone/iPad Safari 기기 검증. 자동 검증은 iPhone Chromium 및 iPhone/iPad WebKit을 사용하며, 실제 카메라·HEIC·소프트웨어 키보드 검증과 구분합니다.
- 실제 유료 AI API 종단 테스트, 공급자별 모델 비교, 제공업체 청구 금액 조회.
- 기초 진단 문제은행, 답 입력·정답 자동 채점, 적응형 난이도, 개인 이해도에 따른 자동 간격 복습. 현재 오답의 첫 복습 날짜는 다음 날입니다.
- 학교 시간표 자동 수집, 외부 캘린더 양방향 동기화, CRASH//WEEK 데이터 자동 가져오기.
- 내신 등급/성적 예측, 최신 가천대 모집요강 검증, 풍부한 월간/주간 습관 리포트와 지각 여부의 실제 측정. 현재 시험 데이터는 0–100 원점수만 지원합니다.
- 자정 이후 취침하는 생활 리듬, 자정을 가로지르는 수업 종료. 현재 수업은 같은 날짜에 종료하고 생활 설정은 기상 시각 < 취침 시각입니다. 이 한계는 입력 오류로 안내합니다. 이른 수업의 전날 준비 시작은 계산·검증합니다.
- 로컬 기록 암호화와 서버 백업. 기기의 다른 사용자·같은 Origin의 스크립트는 localStorage에 접근할 수 있으므로 개인 브라우저 프로필을 사용하고 JSON 백업을 안전하게 보관하세요.

| `Schedule`      | 유형·과목·반복 요일(일=0, 월=1)·nullable 적용 날짜·제외 날짜·시작/종료·준비/이동/여유·준비물 |
| `Block`         | 과제 ID·UTC ISO 시작/종료·수동 고정 여부                                                     |
| `ActiveSession` | 실제 시작·현재 집중 구간 시작·누적 집중 초·목표 시간·일시정지 내역·선택적 구간 기록          |
| `Session`       | 시작/종료·타이머 초·선택적 구간 기록·문제 수·개념·자기평가·오답·복습 날짜·중단 사유          |
| `Settings`      | 한국 시각 기상/취침·최소 수면·집중/휴식/식사·장기 목표                                       |
| `Grade`         | 과목·시험명·nullable 날짜·nullable 목표/실제 원점수                                          |
| `State`         | schema version=1·revision·전체 레코드·승인 계획·실행 취소 스냅샷·복습 완료 ID                |

시간 입력은 한국 시각이고 사건 기록은 UTC ISO 형식으로 저장합니다. 렌더링·요일·자정은 항상 Asia/Seoul입니다. 새 세션은 집중 구간의 실제 겹침으로 날짜별 타이머 초를 집계해 중단 시간을 제외합니다. 구간이 없는 과거 v1 세션만 기존 벽시계 비율 근사치를 유지합니다. 문제 수는 실제 입력을 마친 세션 완료 날짜에 집계합니다.

```text
src/model.ts       Zod 스키마와 타입, 빈 초기 데이터
src/time.ts        한국 시각·요일·날짜 연산
src/engine.ts      배치·복구·시간 검증, AI 결정 검증
src/safety.ts      보호 일정 시작과 고정 일정 충돌
src/storage.ts     버전 있는 로컬 저장 포트와 검증 백업
src/session.ts     정확한 집중 구간·타이머·학습량 집계
src/tasks.ts       제출 확인·주의 목록 분리
src/ai.ts          명시적으로 활성화한 서버 요청 경로
src/App.tsx        여섯 화면·입력 폼·사용자 승인 흐름

server/budget.ts   직렬 처리·영속 일일 한도·토큰 기록
```

`StoragePort`를 서버 저장소로 교체할 때 인증된 사용자 ID로 데이터를 분리하고 revision 기반 충돌 처리를 구현하세요. 현재 JSON 가져오기는 스키마 검증 후 전체 교체입니다. 과거 기록을 자동 병합하거나 삭제하지 않습니다.

## HOW TO DEPLOY SAFELY

**아래는 v1 초기 배포 이력입니다.** 현재 승인된 teambkit.com 게시 절차는 위의 GitHub Pages 워크플로를 따릅니다. `main`은 배포 파일, `feat/study-os-visual-v2`의 `study-os/`는 개발 원본이며, 이전 사이트와 원본은 Git 이력·복구 태그로 보존되어 있습니다.

기존 공개 사이트 교체·main 병합·DNS 변경은 하지 않았습니다. 사용자의 추가 배포 요청으로 독립 Sites 배포를 완료했습니다. Vercel은 teambkit 팀 접근 403과 CLI 미인증, 별도 GitHub 저장소 생성은 통합 권한 부족으로 사용할 수 없었습니다. 배포 기록은 DEPLOYMENT.md를 확인하세요. API 결제·키 등록은 별도 설정입니다.

1. `feat/bkit-study-os-v1` 브랜치의 코드를 검토하고 실제 기록 없이 별도 Preview 프로젝트에 배포하세요. 기본 루트는 `study-os`, 빌드 명령은 `npm ci && npm run build`, 출력 디렉터리는 `dist`입니다.
2. 별도 Preview의 루트 URL을 쓸 때 `APP_BASE=/`로 빌드하세요. 기존 도메인의 별도 경로에 올릴 경우 `APP_BASE=/study-os/`를 유지합니다. 프런트엔드 `.env`에 `VITE_` 비밀키를 넣지 마세요.
3. 정적 호스팅만으로 P0와 Demo AI Mode를 사용할 수 있습니다. `/api`가 없거나 실패하면 규칙 기반 기능이 계속 동작합니다.
4. 기존 GitHub Pages는 **main / 루트**를 사용합니다. `dist`를 저장소 루트에 복사하거나 기존 `index.html`, `CNAME`을 대체하지 마세요. 브랜치를 main에 병합하지 않은 상태에서는 기존 Pages가 새 앱을 공개하지 않습니다.
5. teambkit.com 배포를 원하면 먼저 현재 공개 페이지가 main의 CRASH//WEEK와 다른 이유를 확인하고, 기존 사이트를 보존하는 별도 경로 배포 계획을 승인받으세요. DNS 변경은 필요 여부를 따로 판단하고 승인받습니다.
6. 서버 AI는 인증·사용자 데이터 경계·영속 비용 장부·TLS·허용 Origin·키 관리가 준비된 별도 개인 서버에서만 운영하세요. 본 개발용 Express 서버를 무인 공개 유료 프록시로 사용하지 마세요.
7. HTTPS 또는 localhost에서 PWA 설치·캐시·새로고침을 확인하고 실제 Safari에서 캘린더·파일 가져오기·타이머 백그라운드 전환을 점검하세요. 신규 서비스 워커 범위는 앱 경로에 한정됩니다.
8. 실사용 전 빈 상태를 확인하고 수업·학원 준비 시간을 입력하세요. 첫 주에는 시작 지연·문제 수·과제 제출 누락을 실제 기록과 비교하며 효과를 평가하세요. 성적 향상을 보장하지 않습니다.
