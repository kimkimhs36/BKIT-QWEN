# BKIT 3.2 — 실제 공부용 데이터 안전 인수검수

> 범위: `feat/bkit-3-2-worksheet-ink-pdf`의 디지털 종이·PDF·필기 + 별도 안전 보완 PR #9. 개발 브랜치와 실제 운영 배포는 다릅니다.
>
> **절대 보장 불가:** 어떤 브라우저 로컬 저장소도 기기 분실·사용자 데이터 삭제·저장 공간 정리에서 100% 안전하지 않습니다. 외부에 보관하고 재검사한 ZIP 없이는 장기 보존을 보장하지 않습니다.

## 코드상 저장 구조

| 내용 | 실제 저장소 | 외부 기기 자동 동기화 |
| --- | --- | --- |
| 과제, 시간표, 풀이 텍스트, 오답·복습, 시험 | `localStorage` · `bkit.study-os.v1` | **3.2 전체 기록은 아님** |
| Sleep Guard 설정·회고 | `localStorage` · `bkit.sleep-guard.v3` | 없음 |
| 학교·학원 학습지 원본 사진 | IndexedDB `bkit-private-materials-v1/photos` | 없음 |
| 수면 기록 사진 | IndexedDB `bkit-sleep-photos-v3/photos` | 없음 |
| PDF·학습지 원본, 디지털 필기·페이지 위치·문제 영역 | IndexedDB `bkit-digital-paper-v1` 의 `originals`, `documents` | 없음 |
| 앱 자체 오프라인 실행 자산 | Service Worker Cache Storage | 사용자 기록의 복구 수단 아님 |

기존 개인 Google 동기화는 PDF, 사진, 디지털 필기, 최신 `learning` 데이터를 클라우드에 모두 보관하지 않습니다. "연결됨"을 "모든 자료 백업 완료"로 해석하면 안 됩니다.

## 코드에 적용한 안전 보완

- WebKit iPhone에서 실제 스크롤할 수 있는 상태와 저장된 위치를 확인하는 제스처 테스트로 회귀 검증 개선.
- 설정의 백업 화면에서 브라우저 저장 사용량·추정 한도·영구 저장 보호 상태를 직접 확인.
- 사용자가 `navigator.storage.persist()`를 지원 브라우저에 명시적으로 요청할 수 있게 함(승인이 백업을 대체하지는 않음).
- 학습 JSON 및 Sleep Guard 검증, 임시 쓰기·읽기 검사, 학습/수면 사진 참조 누락 검사, PDF 파일 ID·크기·SHA-256 대조, 필기 문서 스키마 검사.
- ZIP 다운로드 **요청**과 파일 앱에 외부 ZIP이 실제 존재하며 사용자가 다시 선택해 무결성 **검사 완료**한 상태를 구분.
- 마지막으로 사용자가 직접 ZIP 파일을 다시 검사한 시각만 로컬에 표시. 이후 그 파일을 삭제하지 않았는지는 확인할 수 없음.
- 기록을 **교체**하는 복원 방식에는 별도 경고 및 확인 대화상자를 추가. 기존 `recovery` 원본·저널 보존 규칙 유지.
- 보완 테스트를 추가했고, 6환경 전체 E2E는 기능 수정마다 반복하지 않고 최종 PR review 단계에 검증하도록 구성.

## 실제 공부용 합격 체크리스트

아래는 **자동 테스트와 별도로 실제 기기에서 수행할 항목**입니다.

1. **실기기 확인:** iPad Safari의 실제 Apple Pencil 및 Galaxy Tab S7 FE의 S펜(가능한 기기별)에서 펜·손가락·팜 리젝션·스크롤·회전 확인. CSS/Playwright 모의 입력만으로 합격 표시하지 않음.
2. **기본 기록:** 시험과 무관한 샘플 PDF 1개를 올리고 필기 10~20획·문제 답변 1개를 작성. "저장됨" 표시 뒤 탭 종료·재실행해 필기·페이지 위치·답변 유지 확인.
3. **저장 진단:** 설정 → 백업에서 '현재 기기 저장 환경 확인', '내 공부 기록·PDF·필기 원본 정밀 검사'를 실행. 오류가 나오면 실제 공부 자료를 쌓기 전에 원인 해결.
4. **전체 ZIP:** 설정 → '사진 포함 전체 ZIP 내보내기' → iPad **파일 앱** 등 브라우저 밖의 폴더에 실제 저장됐는지 확인.
5. **ZIP 재검사:** '전체 ZIP 백업 검사'에서 방금 저장한 **그 파일을 직접 선택**해 체크섬·자료 원본·PDF/필기 인덱스 검사 통과. 여기서 시험용 복원을 위해 기존 기록을 교체하지 말 것.
6. **격리된 복원:** 별도의 깨끗한 브라우저 프로필/기기로 복원해서 PDF 원본·필기 획·문제와 수면/사진 참조를 실제 대조. 본 기기의 실사용 기록을 덮어쓰며 테스트하지 않음.
7. **오프라인 및 재진입:** 설치형 PWA와 Safari는 서로 다른 저장 영역일 수 있으므로 각각 따로 테스트. 인터넷이 끊겨도 기존 자료를 열 수 있는지 확인.
8. **용량 한계:** 현재 백업은 원본 한 개 20MB, 원본 총량 250MB, ZIP 300MB, 필기 메타데이터 20MB 등의 제한이 있음. 이보다 큰 문제집은 분할하거나 별도 원본 보관이 필요.
9. **실제 학습 시작:** 위 테스트를 통과한 사용 환경에서만 주력 공부자료를 옮기고, 중요한 공부가 끝날 때마다 최신 ZIP 백업을 재검사.

## 릴리스/배포 조건

- TypeScript·build·unit PASS.
- Playwright 6개 프로필 전체 회귀 PASS(동일 최종 소스 SHA 기준).
- 공부 기록 저장 실패/원본 누락/ZIP 무결성 실패를 성공으로 표시하지 않음.
- 실제 아이패드 필기·앱 재진입·원본 ZIP 확인은 사용자 기기 검수 후 별도 PASS.
- 기존 `main` 및 `teambkit.com`은 명시적인 운영 배포 승인 전에는 변경하지 않음.

## 테스트 및 복구 참고

- 최종 코드: GitHub PR #9의 실제 HEAD를 사용한다. 중단된 Codex의 로컬 미커밋 파일에 무조건 덮어쓰지 않는다.
- 저장 충돌 오류가 나오면 다른 탭을 닫되, 기존 원본과 미저장 필기를 먼저 내보낸다.
- 현재 데이터를 지우거나 브라우저 사이트 데이터를 초기화해서 문제를 해결하지 않는다.
- ZIP 복원 전에 항상 현재 기기 데이터의 별도 ZIP 백업을 만든다.
- 3.1 JSON 백업은 3.2의 PDF·필기 원본을 포함하지 않는다.

**이 문서는 실제 기기 검증을 대체하지 않으며, 모든 항목을 통과하기 전에는 데이터가 절대 사라지지 않는다고 주장하지 않는다.**
