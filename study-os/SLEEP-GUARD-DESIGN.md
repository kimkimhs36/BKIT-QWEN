# BKIT Sleep Guard — 설계 v2 (개발 브랜치 전용)

> **배포/병합 금지.** 검증 전에는 운영 사이트에 넣지 않는다. 2026-10-19 기준. 이 문서는 시스템 설계이며 의료 기기나 수면 치료 프로그램이 아니다.

## 해결하려는 문제

- 사용자는 iPhone/iPad를 주로 사용한다. 취침 시간이 되어도 BKIT 웹이 열려 있지 않으면 웹 UI는 화면을 바꾸거나 다른 앱을 감지하지 못한다.
- 기기 화면을 덜 보면서 권장 수면 시간을 확보하는 것이 목표다. 웹으로 '강제 수면', 시각적 최면, 초음파/주파수 유도 등을 약속하지 않는다.
- 공부를 위해 수면을 미루거나, 수면 UI 뒤에서 공부 타이머가 계속 돌아가는 일을 막는다.

## 수면 시간과 흐름

기본 예시(사용자가 변경할 수 있음): **월~금 기상 07:00, 토~일 기상 08:00, 침대에 있는 시간 목표 8시간 30분**.
- 평일 기상 전날: 21:30 화면 내려놓기/취침 준비 → 22:30 침대에 들기 → 다음 날 07:00 기상
- 주말 기상 전날: 22:30 화면 내려놓기/취침 준비 → 23:30 침대에 들기 → 다음 날 08:00 기상
- 이는 실제 수면시간이나 수면 효율 측정이 아니라 **수면 기회를 확보하려는 일정**. 잠드는 데 걸리는 시간은 사람마다 다르므로 필요하면 더 일찍 마무리하도록 조정한다.
- 평일/주말 수면 시각 차이를 너무 크게 벌리지 않도록 안내를 제공하되 사용자에게 매번 점수를 매기지 않는다.
- 서울 시간(UTC+9)을 기준으로 실제 오늘/내일 기상 날짜의 절대 시각에서 전날 취침 목표를 계산한다. 새벽 취침 등 드문 설정에서도 화면이 하루 종일 막히지 않도록 테스트한다.

## 동작 사양

1. 기존 사용자에게는 **기본 OFF**. 설정 저장 시 별도 `bkit.sleep-guard.v1` 로컬 스토리지만 이용한다. 본체 `bkit.study-os.v1` 데이터 모델을 수정하지 않는다.
2. 수면 가드 활성화: 화면 종료 60분 전후로 웹에서 작은 안내, 설정 시각부터 저자극 다크 화면.
3. 설정을 마치기 전에 사용자 스스로 화면을 끄고 싶을 때는 **지금 바로 화면 내려놓기** 버튼으로 즉시 휴식 모드. 취침 1시간 전에는 씻기·침실 정리·기기 내려놓기 체크를 선택할 수 있다. **비어 있는 침대 사진은 선택 가능하지만 업로드, 저장, 내용 분석은 하지 않는다. 본인·욕실 사진을 요구하지 않는다.** 인증 없이도 즉시 취침 가능하며 실제 수면 여부를 검증하지 않는다. 다른 앱이나 기기를 실제로 끄지는 않는다.
4. 긴급한 일을 위한 **30분 예외**와 설정 OFF 제공. 수면이나 사용 패턴을 감시·징벌하지 않는다.
5. 웹이 백그라운드에서 오래 잠들었다가 깨어나도 KST 경계 시각까지의 공부만 기록하도록 공부 타이머를 끊는다. 30분 예외를 허용한 시간은 그 예외 종료 경계까지 반영한다.
6. 미완료 과제를 '완료'로 표시하지 않고, 지금 휴식 모드를 사용했다는 이유로 실제 잔 시간이나 공부를 완료한 것처럼 기록하지 않는다.
7. 취침 모드에서 화면 켜두기 Wake Lock을 해제한다. 빛 효과, 불안 자극 문구, 자동 재생 음악, 시끄러운 알람, AI 비용을 사용하지 않는다.
8. 모바일 안전 영역(Safe Area), 320px 좁은 너비, iPad 가로/세로, 키보드 접근, VoiceOver 역할/레이블, `prefers-reduced-motion`을 확인한다.
9. 기존 BKIT 생활설정의 취침 시간과 Sleep Guard의 취침 목표는 **서로 다른 설정**이며 자동으로 동기화하지 않는다. 혼란을 줄이기 위해 UI를 통합하는 것은 후속 별도 과제다.

## 강한 수면 알림을 원할 때 (선택적 푸시 설계)

- 사용자가 "지금 자!" 같은 강한 문구를 고르더라도 **무한 반복/연속 폭격은 구현하지 않는다**. 여러 번 알림이 울리면 오히려 야간 각성이 증가할 수 있다.
- 사용자가 푸시 수신에 명확히 동의한 경우에만 2개 계획: **취침 75분 전** 마무리 안내, **60분 전** 기기 내려놓기 안내. 이후에는 알림을 보내지 않는다.
- 발송할 시간이 15분 이상 지난 알림은 전송하지 않고, 발송 ID로 중복을 방지한다. 서버 측 저장과 인증이 없으므로 지금은 발송 기능 자체가 없다.
- iOS 홈 화면 웹앱 및 권한 승인, 보안 HTTPS, 서버 발송기·VAPID, 적절한 구독/삭제 UI 구현이 필요한 후속 기능이다. 지금 API 요청이나 비용은 0이다.
- 실제 앱 제한은 iPhone/iPad 스크린 타임과 수면 집중 모드에 맡긴다. 긴급 연락 수단은 유지한다.

## 보류 기능

- PWA 원격 푸시/예약 발송: 사용자 명시적 동의 후 서버 구축 시. 수면을 방해하는 알림 과잉은 금지.
- 설정 클라우드 동기화: 사용자의 인증·개인정보 설계와 충돌 처리를 갖춘 뒤 진행. 현재 기기별 체크는 로컬 메모다.
- HealthKit 수면/스크린 타임 사용 정보 직접 접근: 일반 웹에서는 불가. iOS 네이티브 앱 및 적절한 권한/승인이 별도로 필요하다.
