## 3. 우선순위: 기능 추가보다 효과·안전 증명

### P0 · 학습 시작·복습이 작동하는지 확인 [권고]
**가설:** 홈에서 방황하지 않고 시작할 수 있어야 재방문과 완료 경험이 좋아질 수 있다. 증명 전까지 가설이다.

실행:
1. **경로 점검:** `오늘 → 5분만 시작 → 집중 종료 → 실제 문제/개념 기록 → 다음 날 오답 복습`을 빈 데이터와 실제 입력 시나리오 양쪽에서 점검한다.
2. **익명·온디바이스·동의 기반 평가 설계:** 시작까지 걸린 시간, 시작 버튼 클릭 후 실제 세션 저장 비율, 과제 추가 완료 비율, 복습 카드 다시 떠올림 여부 등을 측정 후보로 정의한다. 사용자가 동의하지 않으면 추가 이벤트 추적 금지. 서버 전송 금지.
3. **작은 사용성 테스트:** iPhone Safari 실기기에서 첫 실행·글자/터치·키보드·시트·스크롤·낮은 밝기·VoiceOver를 관찰. 결과를 재현 가능한 이슈로 기록.
4. **성공/실패의 정의:** 기술적 테스트 통과와 교육적 효과는 별도 지표. 사용자가 직접 기록한 정답 여부 또는 실제 문제 수행 없이 학습 효과를 확정하지 않는다.

수용 기준:
- 기기 1대 이상에서 대표 시나리오 5개를 수동 실행하고 화면/기기/결과/실패 이유를 기록.
- 기존 `tests/review.test.ts`, `tests/e2e/focus-restore.spec.ts`, `tests/e2e/ios-navigation.spec.ts` 녹색 유지.
- 개선 전/후 측정이 없을 때 "집중력 향상" 같은 광고 문구 사용 금지.

### P0 · 로컬 데이터 안전 및 이식 [권고]
현재 `src/storage.ts`의 `bkit.study-os.v1`과 `src/model.ts`의 `version: 1`이 기준. iOS 앱을 만들더라도 Safari localStorage가 자동으로 SwiftUI 저장소로 이전되지 않는다.

수용 기준:
- 오래된 JSON(선택 필드 `reviewProgress` 없음), 현재 백업, 손상된 입력, 너무 큰 백업, 충돌 ID, 기록 유지 및 **원본 덮어쓰기 방지**를 테스트.
- 저장 스키마를 바꾸는 경우 구버전 → 신버전 마이그레이션, 내보내기/가져오기 양방향 호환 매트릭스 작성.
- 자동 동기화·계정·암호화 구현 전 사용자에게 제공된 것처럼 말하지 않음.

### P1 · 학습과학 기반 복습의 검증 [권고]
이미 있는 `review.ts`를 폐기하지 말 것. 오답 메모/정답 가림, 단계별 자가판정 기능은 기초가 있다.

발견된 한계:
- `recordReviewOutcome`은 오직 `remembered / retry` 자가평가와 고정된 3일/7일 간격만 사용. 문제 유형·반복 실패 횟수·정답 채점·장기 기억 지속을 검증하지 않음.
- 3회 성공한 카드는 `reviewsDone`으로 보관. 이후 장기 복습은 자동 예약되지 않음.
- `Session.mistake` 텍스트와 행동 설명만으로는 학습자가 실제로 답을 모르더라도 '떠올렸음' 표시 가능.

우선 후보:
1. **정답 가리기+다시 말하기/풀기** UX 명확화 (답 자체를 모델이 창작하지 않는다).
2. 왜 틀렸는지(개념/계산/시간/해석) 분류는 선택 사항으로 설계해 입력 부담 관리.
3. 간격 정책의 출처·유형별 적합성 확보 후 정책 버전과 재스케줄 테스트 추가.
4. 교육학 근거/성능 검증 전에는 "기억력 n% 향상" 등의 수치 금지.

### P1 · AI 비교실험 / 비용 경계 [권고]
`server/provider.ts`는 OpenAI 호환 인터페이스를 제공하나, 실제 공급자별 정확성·지연·비용 비교와 실서비스 인증 구현의 증거는 없다.

수용 기준:
- 평가셋은 시간표 충돌·잠/식사 보호·과제 마감·실제 기록이 없는 경우·프롬프트 주입·민감 내용·국어/영어/수학 설명 등으로 구분.
- **결정론적 규칙 엔진이 시간 배치 결정권 유지.** AI는 허용된 설명과 학습 피드백만 생성하고 시간/시험 정보 등을 날조하면 실패 처리.
- 후보 모델별 최신 공개 가격과 실제 사용 청구 내역, p50/p95 지연, 정확성, 실패율을 *동일 조건*에서 비교한 후 선택. 예산·호출 권한 승인 없이 유료 실행 금지.
- 계정, 인증, API 키 보호, 사용자별 비용/사용량 분리를 갖추기 전 유료 서버 공개 금지.

### P1 · iOS-native UX 기준 및 성능 [권고]
`study-os/IOS_APP_PLAN.md`의 TabView/SwiftUI 계획을 유지하고, 웹 CSS와 네이티브 시스템 글라스를 혼동하지 말 것.

수용 기준:
- 하단 탭바에는 내비게이션만, 과제 생성은 별도 조작부. 44px 이상 터치 타깃, 접근 가능한 키보드 포커스.
- 유리 굴절은 **조작 계층**에만; 읽어야 할 공부 콘텐츠는 선명하게. `prefers-reduced-motion` 및 `prefers-reduced-transparency` 확인.
- 실제 iPhone Safari에서 FPS/스크롤/오버플로/키보드/시트/오프라인 검증 후 수치와 조건을 기록.
- 나중에 SwiftUI의 `TabView`/시트/버전 관리형 저장소로 옮길 UI 계약을 작성; 웹 애니메이션을 1:1 이식한다고 주장하지 않음.

## 4. 개발 운영 규칙 (오늘부터 적용)

1. **각 변경사항에 관련 연구/제품 ID를 표시.** 예: `R01 시작`, `R02 복습`, `R03 일정안전`, `R04 AI`, `R05 데이터`, `R06 iOS`, `R07 평가`.
2. **주장과 증거를 분리.** [코드 구현], [자동 테스트], [실기기 QA], [학습 효과], [연구 출처 확인]은 서로 다른 단계.
3. **작은 변경+테스트+보존.** 로컬 공부 기록, 스키마, 오래된 백업과 계획 복구는 테스트 없이 변경하지 않는다.
4. **디자인 개선 시 '더 예쁨'만으로 종료하지 않음.** 접근성/가독성/탭 전환/콘텐츠 접근 시간/오프라인을 함께 검토.
5. **외부 리서치는 초안으로 둔 채 코드에 사실로 박지 않는다.** 최종 보고서 입수 후 연결표 갱신.
